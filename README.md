נכנסים לאתר כמנהל → תפריט ⚙️ → **בק אופיס** → **⚙️ הגדרה ראשונית** → "העתקה", ואז ב-Supabase → **SQL Editor** → New query → מדביקים → **Run**.
(זה אותו תוכן כמו `supabase/schema.sql`.)
(אפשר להריץ שוב בכל עדכון — הקובץ לא מוחק נתונים.)

### 2. הגדרות התחברות (Authentication)
- **URL Configuration** → Site URL: `https://yamshopping.com`, ובתוך Redirect URLs להוסיף: `https://yamshopping.com/**` וגם `https://www.yamshopping.com/**`
- **Providers → Email**: להשאיר **Confirm email = פעיל** (חשוב! זה מה שמונע ממישהו אחר להירשם עם המייל שלך)
- **Password** → Minimum length: `8`
- (רשות) **Providers → Google** — להפעלת "כניסה עם גוגל"

### 3. להירשם בתור מנהל
שום מייל לא כתוב בקוד כבעלים. בעלים הוא רק חשבון שסומן כך בתוך Supabase. לכל חשבון שצריך להיות בעלים:
1. להיכנס לאתר עם החשבון הזה פעם אחת (למשל "כניסה עם גוגל"), כדי שהחשבון ייווצר.
2. ב-Supabase → **SQL Editor** → להריץ (עם המייל האמיתי במקום `המייל@שלך`):
   ```sql
   update auth.users set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"yam_owner": true}'::jsonb
   where lower(email) = lower('המייל@שלך');
   ```
3. לצאת מהאתר ולהיכנס שוב. מעכשיו יופיעו לך בתפריט ⚙️ "ניהול האתר", "מי מחובר" ו"בק אופיס".

הסימון נשמר בחשבון עצמו (app_metadata), ומשתמש לא יכול לשנות אותו בעצמו — רק SQL או השרת.

### 3א. לא מצליח להיכנס כמנהל (שכחתי את הקוד)
אם יש שני חשבונות בעלים מסומנים — אפשר להיכנס מהשני ולעזור לראשון.
1. בכניסה לאתר: כותבים את המייל ← **"שכחתי את הקוד"** ← פותחים את הקישור שמגיע למייל ← נפתח חלון לבחירת קוד חדש.
2. המייל לא מגיע? בודקים בספאם ובקידומי מכירות, ובנטפרי — שהמייל מ-Supabase לא נחסם. אפשר גם להיכנס מהמנהל השני: בק אופיס ← 👥 משתמשים ← 🔑 ליד המייל.
3. אם עדיין לא — ב-Supabase: **Authentication ← Users** ← מחפשים את המייל ← **⋮ ← Send password recovery** (או **Delete user** ואז נכנסים מחדש לאתר עם אותו מייל, ומריצים שוב את ה-SQL מסעיף 3).

## 🔒 אבטחה
- קוד הכניסה נשמר מוצפן אצל Supabase — אף אחד (גם לא המנהל) לא רואה אותו
- נעילה זמנית אחרי 5 ניסיונות כניסה שגויים + הגבלות קצב של Supabase
- כל טבלה מוגנת בחוקי RLS: כל משפחה רואה רק את הרשימות שלה, אי אפשר לאשר לעצמך מתכון, להתחזות לשם של מישהו אחר, או לשנות הגדרות אתר
- מפתח ה-AI נשמר רק בשרת ואף פעם לא מגיע לדפדפן
- הספריות נטענות עם בדיקת שלמות (SRI), ומדיניות אבטחת תוכן (CSP) מובנית בקובץ עצמו; `_headers` (לא חובה) מוסיף עוד כותרות אבטחה
- 🛡️ **בלי קוד בתוך ה-HTML:** אין `<script>` בלי src ואין `onclick=` / `onerror=` בתוך HTML (גם לא בטקסט שהקוד מכניס לדף). לכפתור: `data-ui="<פעולה>"` עם המאזין האחד בסוף `js/boot.js`, ולתמונה שנמחקת אם לא נטענה: `data-gone="1"` (או `"parent"`). `node tests/stamp-js.mjs --check` נכשל על כל אחד מהם, והבדיקות רצות עם ה-CSP המחמירה. ב-`vercel.json` יש גם `Content-Security-Policy-Report-Only` בלי `'unsafe-inline'`: מה שהיה נחסם בה נרשם ביומן התקלות ("🛡️ CSP (דיווח בלבד)"), ואם היומן נקי כמה ימים — מעבירים אותה לאכיפה.
